SECTION 00

How to use this reference

Original explanation & engineering guidance

A reliable backtest needs a defensible historical information set, a reproducible research process, and a portfolio that could actually have been traded. A good-looking return curve cannot establish any of those conditions by itself.

This standalone guide is an original educational and engineering companion to the linked report. The source-page map and optional PDF reader give access to the original document. The explanations, toy calculations, workflows, data contracts, and acceptance checks below are newly written guidance. They do not reproduce the report’s full text, empirical charts, bibliography, or proprietary algorithms.

Read Sections 01–07 for the failure mechanisms, Section 08 for model construction, and Section 09 for a repository specification. Section 10 is a manual review checklist; Section 11 defines the terminology. Section 12 links every source page and figure location, including the back matter. All substantive guide text is present in the HTML itself, so a human or an AI can read it without executing JavaScript.

Table G.01 — Research questions and the evidence they require
QuestionUseful evidenceWhat a return curve leaves unresolved
Was the opportunity set realistic?Historical membership and exit-event reconciliation.Which failed, acquired, or newly listed securities were included.
Was each decision feasible at that moment?Publication, receipt, decision, order, and fill timestamps.Whether a signal used tomorrow’s information or an unavailable price.

SECTION 01

Survivorship: reconstruct the opportunity set

Original explanation & engineering guidance Source pages 5–8

What fails

Historical research can quietly condition on future survival. If the data table contains only securities still trading today, the past is evaluated using a population chosen partly by what happened afterward. Delisted companies, failed funds, closed exchanges, retired instruments, and acquired firms can disappear from the analysis. Acquisitions are not necessarily losses, so the sign of the distortion depends on the missing cases.

A related error is using today’s index members for every past date. That choice can include a future entrant before it was eligible and omit a former member while it was eligible. Knowing a company’s later success is itself future information. A historical universe needs both effective membership dates and the times membership announcements became available if announcements influence a strategy.

Small example: removing one failure reverses the result

Consider a synthetic one-period portfolio with equal starting capital in three stocks. The returns include the complete final proceeds for each investment.

Table G.02 — Synthetic survival selection
StockOne-period returnPresent in a “still trading” download?
A+20%Yes
B−50%No
C+10%Yes
All three, equal initial weights(20 − 50 + 10) / 3 = −6.67%Correct full opportunity set
Only A and C(20 + 10) / 2 = +15.00%Conditioned on later survival

The 21.67 percentage-point difference comes entirely from changing the sample. It is not a trading improvement. In a longer simulation, reinvestment, changing membership, cash treatment, and final exit payments all need explicit accounting rather than a simple average.

Data decisions that need to be explicit

  • Permanent identity. Use an instrument ID that survives ticker changes. A ticker is a label with its own validity interval, not a universal historical key.
  • Entry and exit. Store listing, eligibility, membership, suspension, and delisting intervals. State whether the strategy uses announcement dates, effective dates, or a documented delay.
  • Terminal cash flows. Reconcile delisting returns, liquidation proceeds, takeover payments, share exchanges, and subsequent cash holdings. Never silently replace an unknown final return with zero.
  • Missing observations. Preserve the eligible-universe count and separately record which securities have usable features. An unavailable feature is not proof that the security never existed.
  • Unavailable terminal outcomes. Flag them and run bounded assumptions where defensible. Report the uncertainty instead of automatically discarding the affected securities.

Repository acceptance checks

A fixture should include an instrument that enters later, one that leaves, and one that changes ticker. For each simulated decision date, the expected membership set must be known. Adding a future entrant must not change earlier membership. An exit must settle through the ledger. The audit report should show eligible count, scored count, excluded count, and each exclusion reason separately.

For a crypto or fund repository, translate the same principle to discontinued pairs, inactive exchanges, closed funds, and changing venue availability. The relevant population is the one the historical strategy could access, not the current API’s convenient list.

SECTION 02

Information timing: define what was knowable

Original explanation & engineering guidance Source pages 9–13

Four clocks, not one date column

A financial value has an economic period, a public release time, a data-provider receipt time, and a time when your process could act on it. These are different clocks. A quarter ending on 31 March does not make its earnings available on 31 March. A value revised in July does not replace what an investor knew in May.

Table G.03 — Minimal time semantics
FieldMeaningExample of a mistake it prevents
observation_period_endThe period the fact describes.Treating a fiscal period-end as its release date.
published_atWhen this version became publicly available.Using an unreleased earnings figure.
received_atWhen this version reached the historical vendor or pipeline.Assuming instantaneous receipt of a delayed feed.
version_id / revision_atThe vintage and revision history.Backfilling a restatement into older decisions.
decision_at / order_at / fill_atThe strategy decision, order submission, and execution times.Filling an order before the inputs or the order exist.
Availability conditionusable_at = max(published_at, received_at) + processing_delay
usable_at ≤ decision_at ≤ order_at ≤ fill_at

The equalities are allowed only when the simulated mechanism really supports them. An input used at an auction cut-off must be available before that cut-off. If receipt history is missing, state the assumption; do not claim a fully reconstructed historical pipeline.

Revision example

In a synthetic dataset, March-quarter earnings of 1.20 are released on 15 May, received later that day, and revised to 1.00 on 15 July. A 31 March decision cannot use either number. A 31 May decision can use 1.20 after receipt. An August decision can use 1.00. A query returning only the latest record would incorrectly use 1.00 for the May decision.

# Original pseudocode; specify timezone and revision tie-breaks.
def facts_as_of(records, decision_at):
    known = records[
        (records.published_at <= decision_at) &
        (records.received_at + records.processing_delay <= decision_at)
    ]
    return latest_known_version_per_fact(known)

facts = facts_as_of(all_vintages, decision_at)
features = compute_features(facts, universe_as_of(decision_at))
orders = decide(features, positions_known_at(decision_at))
fills = simulate_orders_after_submission(orders)

A fixed reporting lag is an approximation

When original release times and vintages are unavailable, a fixed lag can reduce a timing problem, but it cannot recover history. A lag that is too short can admit unknown information; a lag that is too long creates stale signals. A lag on revised values does not undo revision leakage. Compare several defensible lag assumptions and describe the data limitation directly.

Do not choose the lag that maximizes performance and then present it as a factual reporting process. Inspect lag coverage and the security population available under each assumption. An improved database with deeper coverage can change results through sample composition as well as through corrected information timing.

Corporate actions and price fields

A price series back-adjusted for a future split can embed future information into a historical price level. Suppose a stock traded at 80 and split four-for-one years later. A modern back-adjusted series might display 20 for that past date. A historical rule “buy stocks priced below 25” would then select a stock that actually traded above the threshold.

Adjusted histories can be suitable for return calculations, but price-level rules need the contemporaneous nominal price. Ratios such as EPS divided by price require numerator and denominator to use consistent share units. A split should not change a correctly aligned earnings yield merely because one side of the ratio was adjusted. Dividends, splits, and share exchanges must also be handled consistently in portfolio accounting.

Table G.04 — Choose the field for the question
QuestionData treatmentVerification
Was a stock priced below a fixed currency threshold?Use its actual historical nominal quote.A future split cannot change an earlier eligibility decision.
What was the return earned by a holder?Use reconciled price changes and cash flows, or a documented total-return series.A split creates no economic windfall; dividends are counted once.
What was EPS / price?Align the share basis and the vintage known at the decision.Consistent split conversion leaves the ratio unchanged.
What happened at an announcement?Use release timestamps, exchange sessions, and executable prices.After-hours releases do not become tradable at the earlier close.

Bar-based backtests need the same discipline

A signal calculated using a final closing price usually cannot also assume an order filled at that identical close. With hourly bars, an order submitted after the bar is complete cannot capture movement inside that completed bar. An auction-specific strategy is possible only with a model of the information cut-off, order timing, and execution rules.

A useful leakage test is to append or perturb future records and rerun the past. Earlier features, selections, and orders must remain unchanged. Also perturb a revision issued after the decision; the earlier decision should still use the earlier vintage.

SECTION 03

Narrative confidence: test an explanation

Original explanation & engineering guidance Source pages 14–16

A coherent explanation is not a validation result

A researcher can often explain either sign of a relationship. Higher debt might require a risk premium, or it might signal distress that investors price badly. A persuasive explanation helps specify a mechanism, but it does not establish which prediction will survive a new sample. Explaining a pattern after seeing the result adds little independent evidence.

Separate three statements: a proposed economic mechanism, a measurable prediction, and an observed test result. Keep them in different fields in the experiment record. If the prediction changes after observing performance, record a new hypothesis rather than rewriting the original one.

Table G.05 — A hypothesis that can be challenged
FieldOriginal example
MechanismLiquidity-constrained investors may react slowly to new public information.
PredictionA predeclared signal predicts returns after a feasible execution delay, net of estimated costs.
Alternative explanationThe signal merely selects high-beta or smaller securities.
Disconfirming evidenceThe relationship disappears with a feasible delay, matched controls, or an untouched evaluation period.
Decision ruleEvaluate with fixed definitions and compare a simple baseline before adding complexity.

Longer history and relevance are different goals

A longer sample can cover more states of the world, but it may combine different market structures. A shorter sample can be more relevant but leave fewer independent observations. A million observations from correlated securities or overlapping return windows are not a million independent experiments.

Show full-period results alongside predeclared subperiods and rolling diagnostics. Record policy, market structure, data-methodology, and universe changes that could alter interpretation. Do not delete an inconvenient period simply because it harms the strategy. If a regime is part of the rule, its classifier must itself use information available at each historical decision.

Useful diagnostics

  • Report the signal’s direction and magnitude by subperiod, sector, country, liquidity band, and market state.
  • Distinguish a weak average from a sign-changing relationship. The implementation response can differ.
  • Show sample size, overlap, concentration, and uncertainty next to performance.
  • Audit whether a new narrative was adopted after each disappointing interval.
  • Test the same declared method on genuinely new data, preserving definitions and acknowledging differences in market access.

A machine learning model can be useful without a simple narrative. It still requires feasible inputs, an honest evaluation process, and an implementable portfolio. An intuitive story and a complex model are both research objects that can be wrong.

SECTION 04

Repeated search: evaluate the research procedure

Original explanation & engineering guidance Source pages 17–18

The winner is selected from a hidden competition

Searching many factors, windows, universes, thresholds, lag assumptions, and portfolio rules makes a lucky winner more likely. The effective competition includes unreported manual changes, not just a formal grid search. A high score for the best result can describe selection luck rather than repeatable predictive power.

In a synthetic experiment, if 20 independent tests each have a 5% false-positive probability under the null, the chance of at least one positive is 1 − 0.95²⁰ ≈ 64.15%. Real financial experiments are often dependent, so this calculation is an illustration rather than a correction formula for a real search.

Test the complete rule

The object to evaluate is the procedure that chooses factors, fits transforms, estimates risk, selects parameters, and constructs trades. Choosing today’s winning factors and replaying them into the past tests a hindsight-selected portfolio. A historical simulation of a selection rule must repeat the selection using only data known at each selection time.

Walk-forward mechanics

  1. Define a training window, selection method, evaluation horizon, and update schedule before examining the final test.
  2. At each boundary, fit every time-series estimator only on observations available before that boundary. Cross-sectional transforms may use securities known at the same decision, under a documented universe rule.
  3. Exclude training labels whose outcome windows extend beyond the training boundary. Overlapping labels can leak evaluation outcomes into training even when rows are sorted by date.
  4. Freeze the selected rule for the next evaluation interval and simulate feasible orders.
  5. Stitch only those successive evaluation returns together. Keep training and validation performance in separate outputs.

An untouched final test loses its status once it influences further changes. The next version can still be researched, but the previously viewed interval is now part of development history. A second test requires genuinely unobserved data or a clearly limited claim.

The experiment ledger

{
  "experiment_id": "example-0042",
  "hypothesis_written_before_run": true,
  "git_commit": "REPLACE_WITH_ACTUAL_COMMIT",
  "data_snapshot_hash": "REPLACE_WITH_ACTUAL_HASH",
  "parent_experiment_id": "example-0031",
  "changed_assumption": "execution delay",
  "train_end": "CONFIGURED_TIMESTAMP",
  "validation_end": "CONFIGURED_TIMESTAMP",
  "untouched_test_accessed": false,

The placeholders are deliberate; this is a proposed record format, not an executed study. Log disappointing runs and excluded variants. A reproducible ledger is more informative than a folder containing only screenshots of winning strategies.

Failure-focused checks

Randomized or deliberately uninformative signals should not systematically produce strong evaluation results. Moving labels into the future should trip a boundary assertion. Appending future data must not change earlier selected parameters. These tests target hidden leakage or selection machinery; they do not prove that a strategy has alpha.

SECTION 05

Signal life and trading: optimize net feasibility

Original explanation & engineering guidance Source pages 19–23

Prediction is not the same as capture

A signal may predict an outcome that occurs before the first feasible trade. Its usefulness depends on the time between observation and execution, the speed at which the opportunity fades, and the cost of changing positions. Gross returns from a frictionless simulation are a diagnostic, not the final implementable result.

Keep four controls distinct: how often new information is processed, how often desired positions are recomputed, how often orders are allowed, and how much trading is allowed. A portfolio can be checked frequently while changing only a small fraction of holdings. A turnover cap and a rebalance schedule are different rules.

Declare the turnover convention

Let w⁻ be the portfolio’s weights immediately before trading, after price drift and cash flows, and w⁺ the intended post-trade weights. For a simple fully invested long-only portfolio with a consistent cash convention:

Turnover definitionsT_two_way = Σᵢ |wᵢ⁺ − wᵢ⁻|
T_one_way = 0.5 × T_two_way

Synthetic example: changing stock weights from 60/40 to 50/50 sells 10% of NAV and buys 10% of NAV. Two-way turnover is 20%; one-way turnover is 10%. If cost is 10 basis points on every traded dollar, that rebalance costs 0.20 × 0.001 = 0.0002, or 2 basis points of NAV. Applying the 10-basis-point rate to one-way turnover would count only half the traded dollars.

For long/short portfolios, leverage changes, external cash flows, derivatives, and futures rolls, specify the denominator and eligible trade types separately. Do not assume that every reported turnover statistic has the same economic meaning.

Table G.06 — Cost components with different drivers
ComponentTypical basisNeeded historical input
Commissions and venue chargesExecuted notional or a fee schedule.Fee schedule, order/fill notional, minimum charges if applicable.
Spread crossingBid/ask quotes and execution side.Quotes or a documented spread proxy available at execution.
Market impact and slippageSize, participation, liquidity, urgency, execution mechanism.Volume, prices, order size, and an explicit model.
Borrow fees and financingPosition value integrated through time.Historical rate, accrual basis, short positions, cash balances.
Short dividends and corporate actionsActual holder obligations and events.Dividend and event records reconciled against holdings.
Taxes or instrument-specific costsDefined jurisdiction/instrument assumptions.Configured rules; do not hide them inside a universal bps rate.
Ledger relation, not a shortcut to annual metricsnet_pnl = mark_to_market_pnl + cash_flows − execution_costs − borrow_costs − financing_costs

Spread, impact, and slippage definitions must avoid double-counting. A price-based slippage estimate may already include the spread. Turnover should compare desired positions with drifted current holdings, not simply with last rebalance’s target weights.

Why less trading is not automatically better

A tight turnover cap saves cost but can leave the portfolio holding a stale signal. The relevant comparison is a constrained portfolio’s net result against an otherwise matched baseline. A strategy with strong, rapidly fading information may justify more trading; another may have no viable turnover level once costs and delay are included.

Evaluate a predeclared sensitivity grid of delay, cost, liquidity, and turnover constraints. Record every grid point. Keep the same data, risk target, universe, leverage convention, and validation protocol when comparing rebalance schedules. A result under one cost assumption does not establish robustness under worse execution conditions.

Interactive synthetic cost-and-delay model

This teaching model assumes a constant gross annual opportunity, exponential decay between rebalances, fixed one-way turnover per rebalance, and linear cost per traded dollar. It does not simulate stock returns, adaptive orders, liquidity, borrow, volatility, or compounding. Its rates are arithmetic annual rates, not CAGR. Changing the settings illustrates the tradeoff rather than finding a deployable optimal schedule.

Lab G.01 · synthetic mechanics
λ = ln(2) / half_life
average_retention(h) = (1 − exp(−λh)) / (λh)
gross_rate(h) = 12% × average_retention(h)
annual_cost(h) = 2 × one_way_turnover × (cost_bps / 10,000) × 252 / h
net_rate(h) = gross_rate(h) − annual_cost(h)
Default five-day interval: retention 84.51% · gross 10.14% · annual cost 2.02% · net 8.13%.

The toy model allows zero turnover with an unchanged gross opportunity; that setting exposes the model’s limitation and is not a feasible claim about a changing portfolio.

Execution-delay checks

Compare a diagnostic idealized fill with the earliest realistically allowed fill, then longer delays. Plot net performance against delay rather than reporting a single point. If the signal vanishes before execution, better portfolio optimization does not repair the timing problem. Log order rejection, participation limits, partial fills, suspensions, and cash left uninvested.

SECTION 06

Extreme values: preserve information and accounting

Original explanation & engineering guidance Source pages 24–33

Diagnose before transforming

An extreme number can be a unit mismatch, a split inconsistency, a stale field, a tiny denominator, a real economic event, or an unusually informative observation. These require different responses. A smooth time series is not by itself evidence that a data-cleaning choice is correct.

Keep raw values immutable. Store corrected values, flagged values, and modeling transforms as separate fields with a reason, rule version, and timestamp. A transform may limit an input’s influence; it must not silently rewrite actual realized portfolio returns. Genuine losses and windfalls belong in the return ledger.

Table G.07 — Four distinct actions
ActionWhat changesMain consequence
Correct a documented errorReplace an incorrect raw fact using an auditable source.Improves accuracy when the correction is justified and vintage timing is preserved.
Winsorize / clipCap a feature outside specified bounds; retain the row.Reduces magnitude while losing tail-distance information.
Trim / removeExclude observations under an explicit rule.Changes the analyzed sample and can introduce selection effects.
TransformApply a function such as log, rank, or standardized score.Changes the signal representation and potentially its economic meaning.

Winsorization is a policy, not an automatic truth

Clipped featurex_clipped = min(max(x, lower_bound), upper_bound)

Bounds can be physical limits or estimated percentiles. A percentile rule requires a declared universe, estimation window, missing-value policy, and quantile interpolation rule. A cross-sectional bound at date t may use the eligible values known at t. A time-series bound fitted from the full future sample is leakage.

Run sensitivity around the bounds and report the fraction of values affected. If conclusions depend on one cutoff, that dependence is part of the result. Do not select a clipping percentile solely because it improves the same evaluation sample later used to claim success.

IQR screening and skew

Interquartile range screeningIQR = Q₃ − Q₁
lower = Q₁ − k × IQR
upper = Q₃ + k × IQR

Here Q₁ and Q₃ are the 25th and 75th percentiles, and k is a declared nonnegative multiplier. This rule does not require a normal distribution, but skew and heavy tails can make an ordinary symmetric fence unsuitable. Inspect the distribution and economic meaning. A log transform can help with strictly positive, heavily skewed quantities such as size; it cannot simply be applied to zero or negative observations.

If IQR is zero, record a fallback rather than letting division or a degenerate fence silently determine eligibility. Treat “flagged for review” differently from “removed from the investment universe.”

Z-scores, ranks, and normal scores

Three representationszᵢ = (xᵢ − mean(x)) / sd(x)
uᵢ = (rankᵢ − 0.5) / n
normal_scoreᵢ = Φ⁻¹(uᵢ)

The standard-deviation denominator convention must be specified. Z-scoring recenters and rescales data; it does not turn a skewed distribution into a Gaussian one. Average ranks are a reasonable declared tie policy. Midrank plotting positions keep u away from 0 and 1, avoiding infinite inverse-normal values. With a finite sample and ties, transformed scores approximate normal quantiles; they are not an exact continuous standard normal distribution, nor necessarily exact unit sample variance.

Table G.08 — What each transform keeps
RepresentationKeeps ordering?Keeps distance?Important limitation
Raw featureYes, if directly comparable.Yes, in original units.Incompatible scales can dominate a combined score.
Z-scoreYes when sd > 0.Yes, relative to estimated dispersion.Large tails remain influential; mean and sd can be unstable.
Rank / percentileYes, with tied values sharing ranks.No original distance.A large gap and a tiny gap can become equivalent adjacent ranks.

Do not mistake exposure changes for a better transform

A signal proportional to raw momentum may be net long when most instruments have positive momentum and net short when most are negative. A centered ranking can suppress that common directional component. If one transform appears superior, compare market exposure, leverage, volatility, concentration, and turnover as well as predictive metrics. Match these conditions before attributing the difference to preserved signal information.

Aggregation needs an accounting definition

A mean of stock-level ratios is generally different from a ratio of aggregate quantities. For earnings yield, Σ earnings / Σ market_cap is a market-cap-weighted average of individual yields only when the same compatible earnings, capitalizations, and covered instruments are used. Differences in share classes, dilution, currency, missing fields, or denominator timing break that identity.

Synthetic example: company A has earnings 1 and capitalization 10; B has earnings 1 and capitalization 100. Their yields are 10% and 1%. The simple mean is 5.5%; the aggregate yield is 2 / 110 ≈ 1.82%. Neither number should be relabeled as the other. Large ratio spikes should prompt reconciliation of numerator, denominator, units, and coverage before clipping.

Event returns require a suitable counterfactual

Abnormal return means observed return minus a declared expected or reference return. Subtracting a broad index may leave size, sector, risk, or style differences in the residual. A comparison group selected using future information introduces its own leakage. Build controls from characteristics and eligibility known before the event.

ARᵢ,t = rᵢ,t − reference_returnᵢ,t
CARᵢ[a,b] = Σₜ₌ₐᵇ ARᵢ,t

A summed cumulative abnormal return is not a compounded wealth return. A market-model alternative uses rᵢ,t − (αᵢ + βᵢr_market,t), with α and β estimated in a pre-event window. Document event-time alignment, overlapping events, peer construction, weighting, and the aggregation method.

Synthetic example: the event stock gains 5%, the broad market gains 2%, and an appropriate matched peer group gains 4%. The two excess returns are 3% and 1%. Different counterfactuals answer different questions; a positive pre-event residual is not by itself proof of leaked information.

SECTION 07

Short-side feasibility: separate signal from access

Original explanation & engineering guidance Source pages 34–39

A combined spread can hide where the information lives

A factor can produce a good long/short spread through useful long selections, useful short selections, or both. A single correlation or spread statistic does not show whether a long-only mandate can capture the effect. Inspect quantile returns and the two legs relative to the same declared reference.

Leg attribution for a matched referencelong_excess = return(top_group) − return(reference)
short_excess = return(reference) − return(bottom_group)
spread = long_excess + short_excess = return(top_group) − return(bottom_group)

These are return differences before short-specific financing and execution. A funded, leveraged, or cash-collateralized portfolio needs its own ledger and denominator. A futures hedge creates a different implementation from a short basket of individual stocks.

Table G.10 — Synthetic payoff asymmetry
SignalTop groupReferenceBottom groupLong excessShort excessSpread
A8%5%4%3%1%4%
B6%5%−1%1%6%7%

Signal B has the larger spread but relies mainly on the bottom group underperforming. A long-only portfolio receives a different opportunity from a feasible short portfolio. This synthetic example says nothing about which real factor currently works.

Borrow is a historical constraint

A simulator needs time-stamped borrow availability, available quantity, rate, and relevant trading restrictions. Difficult-to-borrow instruments may be precisely the instruments a signal wants to short. Restricting that basket changes the strategy, not just its fees. Rebuild the feasible portfolio and recalculate all exposures and trades.

Table G.11 — Required short-side states
StateSimulation behavior to specifyAudit output

No historical borrow datasetShow the assumption explicitly and separate the idealized result.Coverage gaps and conservative sensitivity results.
Simplified fee accrualborrow_cost = Σ_days |short_market_value_day| × annual_borrow_rate_day × day_fraction

The day fraction follows the contract or configured convention; 1/365 is only an example. Accrue on actual changing positions, not the original short value for the whole experiment. Borrow costs, short sale proceeds, collateral income, and margin funding are separate items.

Concentration is a joint research and execution choice

Holding fewer names can emphasize stronger scores, but also increases idiosyncratic risk, crowding, borrow dependence, liquidity stress, and sensitivity to a small set of observations. More names can diversify, but add weaker signals and possibly more trading. Neither raw return nor position count alone decides the choice.

effective_number_of_positions = 1 / Σᵢ pᵢ²
pᵢ = |position_valueᵢ| / Σⱼ |position_valueⱼ|

This concentration measure is not a count of independent bets. Correlated positions can produce many names but little diversification. Compare concentration variants at matched leverage, risk targets, cost assumptions, access rules, and turnover conventions. Report top-position contribution and sector/country clustering.

Choose between implementations with complete costs

Compare an idealized long/short signal diagnostic, a historically feasible long/short implementation, and a long stock portfolio with a feasible index hedge if the mandate allows it. The hedge’s basis risk, roll, margin, financing, and imperfect beta offset belong in the comparison. A theoretical short basket is a useful upper-bound diagnostic only when labeled that way.

SECTION 08

Build a model: keep signals, risk, and portfolios distinct

Original explanation & engineering guidance Source pages 40–47

A reference model for a reproducible repository

The following is a proposed generic five-style research specification. It illustrates how to translate the preceding controls into a pipeline. It is not a reproduction of the report’s empirical study, a claim of profitable performance, or an exact implementation of its proprietary methods. Choose an accessible point-in-time dataset and record its limitations before selecting model complexity.

“Earnings growth” and “momentum” are not complete formulas. Specify fiscal horizon, units, sample exclusions, denominator handling, return method, lookback, direction, and availability timestamps. A forecast for one fiscal year cannot be blindly compared with a later forecast for a different fiscal year. A near-zero denominator should trigger an explicit policy rather than an arbitrary epsilon chosen after viewing returns.

Separate factor normalization and factor weighting

Normalization sets the scale and interpretation of each feature. Factor weighting decides the mixture of those normalized features. Combining raw features in different units can make one feature dominate even when numerical weights are equal. Conversely, equal model weights do not imply equal risk contributions, because factor signals and resulting portfolios can be correlated.

Combined stock scorescoreᵢ,t = Σₖ aₖ,t × transformed_featureᵢ,k,t

Here a is a model coefficient, not a stock weight. The portfolio constructor subsequently maps scores, risk, constraints, and current holdings into stock positions. A score’s missing-value policy must be stated: require all inputs, use a predefined subset, or use a train-fitted imputation method with coverage flags. Renormalizing across present features changes the model by security and needs its own audit.

Table G.13 — Factor mixing methods and their assumptions

Illustrative unconstrained mean-variance relationa ∝ Σ_factor⁻¹ μ_factor
portfolio_variance = aᵀ Σ_factor a
risk_contributionₖ = aₖ(Σ_factor a)ₖ / sqrt(aᵀ Σ_factor a)

The inverse-covariance relation is a teaching expression; production implementations should solve a declared constrained and regularized problem. A near-singular covariance matrix can turn small estimation errors into large unstable weights. Bounds, shrinkage, turnover penalties, and solver diagnostics change the feasible solution and belong in the configuration.

Expected returns and covariances may be estimated with a rolling or expanding window. A rolling window adapts but discards older data; an expanding window increases sample size but can respond slowly to change. Estimate only on completed historical outcome windows. If factor outcomes span the next month, that month’s return cannot enter an estimate made at the start of the month.

Risk estimates are inputs, not realized guarantees

A target volatility or tracking error is a model forecast under constraints, not a promise about realized risk. Show forecast and realized risk separately. Compare volatility, tracking error, beta, gross and net exposure, tail losses, and concentration through time. Optimization can favor weights where estimation errors make risk look unusually low.

Tail dependence and covariance answer different questions. Low ordinary correlation does not guarantee low joint losses in stress. A tail-based method also needs enough observations, defensible tail thresholds, and out-of-sample validation. The source’s brief descriptions do not provide enough implementation detail to claim exact proprietary replication.

Country and sector controls at two stages

A cross-country or cross-sector factor can reflect structural differences rather than within-group stock selection. One approach is to normalize within a group known at the decision date. Another is to residualize the signal against a declared group or risk-exposure design matrix. Both change the signal; neither replaces portfolio-level exposure checks.

Illustrative cross-sectional residualizationx = Bγ + ε
γ̂ = argminγ Σᵢ sample_weightᵢ × (xᵢ − Bᵢγ)²
neutralized_signal = x − Bγ̂

Declare country and sector classification vintages, tiny-group handling, regression weights, intercept treatment, and restandardization. A zero mean signal within each sector does not ensure zero sector exposure after nonlinear selection, position limits, borrow restrictions, or liquidity constraints. Recheck realized portfolio exposure.

Two different portfolio topologies

In Route A, opposing feature views on the same stock can offset inside a combined score before one stock portfolio is constructed. In Route B, one sleeve might buy a stock while another sells it. If sleeves trade independently, both legs may generate costs. If a manager aggregates holdings and nets orders, the economic implementation changes and requires an explicit policy. Do not assume that independent funds or external products can net trades automatically.

The smallest coherent research architecture

Separate ingestion, availability queries, features, transforms, model estimation, portfolio construction, execution, accounting, and reporting. Implement controls before tuning performance

  1. Create tiny deterministic fixtures for membership, vintages, splits, delayed execution, missing fields, costs, and borrow. Their expected historical information sets and cash flows should be hand-checkable.
  2. Implement the as-of query and an accounting baseline. Confirm that buy-and-hold positions reconcile across corporate actions and exits.
  3. Add simple features and static mixing. Preserve lineage and coverage before adding a sophisticated estimator.
  4. Add constrained construction and realistic execution. Produce an exception ledger and compare idealized with feasible outcomes.
  5. Add the chronological research protocol, experiment ledger, and fixed reporting conventions.
  6. Only then compare more complex estimators, using the same frozen evaluation rules.
